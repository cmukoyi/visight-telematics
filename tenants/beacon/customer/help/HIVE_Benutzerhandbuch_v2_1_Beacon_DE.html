HIVE Tracking

Fassen Sie Ihre BLE-Tags zu überwachten Gruppen zusammen und werden Sie benachrichtigt, sobald sie sich voneinander entfernen. Entwickelt für Reisegepäck, Werkstattwerkzeug, Flottenmittel und alles andere, was zusammenbleiben soll — im Stand wie unterwegs.

Gemeinsam unterwegs — Schluss mit Fehlalarmen

Tests im Alltag zeigten, dass HIVE falsche Überschreitungswarnungen auslöste, wenn Gruppen gemeinsam im Fahrzeug unterwegs waren. v2.0 führt die veralterungsbewusste Auswertung ein: HIVE vertraut einer „Überschreitung“ nicht mehr, wenn sie aus Positionsmeldungen von unterschiedlichen Punkten einer Fahrt zusammengesetzt ist.

  • Zeitliche Kohärenz — HIVE bestätigt eine Überschreitung nur aus Positionen, die zeitlich dicht beieinander erfasst wurden, sodass eine Fahrt nicht mehr wie eine Trennung aussieht
  • Beständigkeit erforderlich — eine Überschreitung muss durch frische, konsistente Hinweise gestützt sein, bevor sie bestätigt wird; kurze Artefakte bleiben „vermutet“ und lösen sich von selbst auf
  • Warnungen für mehrere Tags (v2.1) — entfernen sich mehrere Tags gemeinsam, nennt die Warnung, wie viele sich abgespalten haben, und nicht nur eines
  • Schutz vor Fehlmessungen (v2.1) — eine einzelne verirrte GPS-Meldung kann keinen Fehlalarm auslösen; eine echte Trennung wird trotzdem binnen weniger Minuten bestätigt
  • Keine Einrichtung nötig — die neue Auswertung läuft automatisch und gilt für jeden Hive

01

Überblick

HIVE ist eine Funktion zur Näherungsüberwachung von BLE-Tag-Gruppen. Sie wählen eine Gruppe von 2 bis 5 Tags, die zusammengehören — ein Reiseset, eine Werkzeugsammlung, eine Lieferladung —, und HIVE überwacht deren Positionen. Entfernt sich ein Tag weiter als der von Ihnen eingestellte Abstand von den übrigen, erhalten Sie eine Warnung.

HIVE arbeitet mit allen iBeacon- oder Eddystone-BLE-Tags, die bereits in Beacon Telematics registriert sind. Es nutzt dieselben Crowdsourced-Ortungsdaten, die Ihre Tags ohnehin melden — ohne Spezialhardware und ohne Anchor. Tags melden ihre Position immer dann, wenn ein Telefon mit einer kompatiblen App in der Nähe vorbeikommt; die Datenqualität ist deshalb in belebten Gegenden am besten und in ruhigen naturgemäß dünner.

Seit v2.0 nutzt HIVE eine veralterungsbewusste Auswertung. Wenn Ihr Hive gemeinsam unterwegs ist (im Auto, auf dem Rad, in Ihrer Tasche beim Gehen), unterscheidet HIVE zwischen „wirklich getrennt“ und „sieht nur getrennt aus, weil die Positionsmeldungen an verschiedenen Punkten der Strecke entstanden sind“ — und löst so keine Fehlalarme aus.

→ Auf einen Blick

2–5 Tags pro Hive gruppieren · Konfigurierbare Abstandsschwelle · Mobilitätsprofil je Hive · 60 Tage operative Laufzeit · 60 Tage Archivaufbewahrung · Option zum endgültigen Löschen · Veralterungsbewusste Auswertung (neu).

02

Neu in v2.0

New

v2.0 ist ein umfangreiches Update, das sich auf ein einziges Problem konzentriert: HIVE kam mit Hives in Bewegung nicht gut zurecht. Wenn Ihr Reiseset schon einmal eine „Überschreitungs“-Warnung ausgelöst hat, während Sie nur vom Supermarkt nach Hause gefahren sind, ist diese Version für Sie.

Das Problem

Die Positionen von BLE-Tags werden von vorbeikommenden Telefonen gemeldet — typischerweise alle 2 bis 5 Minuten. Steht Ihr Hive still, ist das unproblematisch: Eine 3 Minuten alte Position stimmt noch ungefähr. Bewegt sich Ihr Hive aber mit 40 km/h im Fahrzeug, liegt eine 3 Minuten alte Position über 2 km von dort entfernt, wo sich das Tag tatsächlich befindet.

Die alte Version von HIVE berücksichtigte das nicht. Sie verglich die frische Position eines Tags mit der älteren Position eines anderen, sah sie über einen Kilometer auseinander und löste eine Überschreitungswarnung aus — obwohl beide Tags friedlich nebeneinander im Kofferraum desselben Autos lagen.

Die Lösung

HIVE verwendet jetzt eine veralterungsbewusste Auswertung. Bevor eine Überschreitung festgestellt wird, prüft HIVE, ob die verglichenen Positionen zeitlich nah genug beieinander erfasst wurden, um verlässlich zu sein. Zwei Meldungen im Abstand von zehn Minuten beschreiben während der Fahrt zwei verschiedene Punkte Ihrer Route und nicht den Abstand zwischen zwei Tags — HIVE weigert sich daher, daraus eine Überschreitung zu bestätigen. Eine Überschreitung wird nur bestätigt, wenn frische, zeitlich abgestimmte Meldungen durchgängig eine echte Trennung zeigen. Kurze Artefakte durch das Unterwegssein erscheinen als „vermutet“ und lösen sich von selbst auf, sobald Sie anhalten.

Was Sie tun müssen

Nichts. Die veralterungsbewusste Auswertung läuft automatisch. Es gibt keine neuen Einstellungen, und bestehende Hives profitieren unmittelbar nach dem Upgrade vom neuen Verhalten.

→ Ein wichtiger Kompromiss

Solange Ihr Hive gemeinsam unterwegs ist, kann eine echte Trennung während der Fahrt zunächst nur als vermutete Überschreitung erscheinen, bis Sie anhalten und frische, zeitlich abgestimmte Meldungen sie bestätigen. Für die meisten Nutzer (deren markierte Gegenstände bei ihnen sind) ist das genau richtig — während der Fahrt lässt sich mit einer Warnung ohnehin nichts Sinnvolles anfangen.

03

Funktionsweise

Jedes Mal, wenn einer Ihrer markierten Gegenstände eine neue Position meldet, wertet HIVE den Hive neu aus. Es berechnet den Abstand zwischen jedem Tag-Paar der Gruppe und ermittelt den größten Abstand — den Gruppendurchmesser. Überschreitet der Durchmesser Ihre Schwelle und wird die Trennung durch zeitlich abgestimmte Meldungen bestätigt, wird eine Warnung ausgelöst.

Der Zustandsautomat der Warnungen

Warnungen werden nicht beim ersten Anzeichen ausgelöst — das würde Rauschen durch GPS-Schwankungen und kurze Grenzfälle erzeugen. Stattdessen durchlaufen Hives eine bewusst gestufte Zustandsfolge:

OK
→
PENDING
→
BREACHING
→
RESOLVING
→
OK
Abbildung 1. Zustandsautomat der Warnungen — für den Eintritt in die Überschreitung ist eine Bestätigung nötig, für die Rückkehr zu OK eine Hysterese.

Eine vermutete Überschreitung versetzt den Hive in den Zustand PENDING, während auf eine bestätigende Meldung gewartet wird. Ist sie bestätigt, wechselt er zu BREACHING und die Warnung wird versendet. Kehrt das entfernte Tag zurück, wird der Hive nicht sofort zurückgesetzt: Er muss deutlich unter die Schwelle fallen, bevor er über RESOLVING zu OK zurückkehrt.

Ausreißer-Erkennung

Wird eine Überschreitung ausgelöst, ermittelt HIVE, welches Tag sie verursacht hat, indem es zählt, an wie vielen Paaren oberhalb der Schwelle jedes Tag beteiligt ist. Das Tag mit den meisten überschreitenden Paaren wird als Ausreißer markiert — meist dasjenige, das sich entfernt hat — und in Warnungen sowie in der Detailansicht hervorgehoben. Stehen zwei Tags gleichauf, wählt HIVE dasjenige, das am weitesten von der übrigen Gruppe entfernt ist, sodass das genannte Tag immer tatsächlich weit entfernt ist.

Ein Tag oder mehrere Tags trennen sich

Ihre Überschreitungsmeldung passt sich der Zahl der Tags an, die die Gruppe verlassen haben:

  • Ein Tag entfernt — die Warnung nennt es direkt, z. B. "PB708-475 has separated from Mobile Kit — now 1.1 mi from the group."
  • Mehrere Tags entfernt — die Warnung teilt mit, dass sich die Gruppe geteilt hat und wie viele Tags sie verlassen haben, z. B. "Mobile Kit has split — 2 tags have separated from the group (PB708-475 and 1 other)."

Die Benachrichtigung nennt ein stellvertretendes Tag plus eine Anzahl; die Detailansicht listet jedes Tag mit seinem Abstand auf, sodass Sie stets genau sehen, welche sich entfernt haben. Die Anzahl gibt wieder, wie viele Tags tatsächlich jenseits der Schwelle liegen — Tags, die zusammengeblieben sind, werden nie mitgezählt, selbst wenn mehrere Tags an der Überschreitung beteiligt sind.

Veralterungsbewusste Auswertung (v2.0)

Bevor der oben beschriebene Zustandsautomat eine Überschreitung bestätigen kann, führt HIVE eine Veralterungsprüfung durch. Jeder paarweise Abstand wird nur dann als belastbar angesehen, wenn die beiden Positionen zeitlich dicht beieinander erfasst wurden (innerhalb weniger Minuten, je Mobilitätsprofil abgestimmt). Eine „Überschreitung“, die nur auf zeitlich nicht zusammenpassenden Positionen beruht — die typische Signatur einer gemeinsam reisenden Gruppe —, bleibt im Zustand SUSPECTED und wird nie bestätigt. Sie löst sich von selbst auf, sobald frische, zeitlich abgestimmte Meldungen eintreffen. Eine Überschreitung wird nur bestätigt, wenn zeitlich kohärente Meldungen durchgängig eine echte Trennung zeigen.

Warum eine echte Trennung ein paar Minuten bis zur Bestätigung braucht

Trennt sich ein Tag wirklich, sehen Sie kurz eine Überschreitung im Zustand SUSPECTED, bevor sie zu CONFIRMED wird. Diese kurze Wartezeit ist beabsichtigt: HIVE bestätigt erst, wenn die Trennung einige Minuten angehalten hat, gestützt durch frische Ortungsmeldungen. Damit wird die gelegentliche schlechte GPS-Messung abgefangen — eine einzelne verirrte Meldung eines vorbeikommenden Telefons mit schwachem Signal kann ein Tag kurzzeitig weit von der Gruppe entfernt verorten, und die Beständigkeitsprüfung verhindert, dass dieser einmalige Aussetzer einen Fehlalarm auslöst. Eine echte Trennung übersteht diese Wartezeit mühelos und wird bestätigt; ein kurzzeitiger Aussetzer wird durch die nächste gute Meldung widerlegt und verschwindet unauffällig. Wichtig: Der bestätigende Beleg kann von jedem Tag stammen — eine echte Trennung wird also auch dann bestätigt, wenn das abgewanderte Tag selbst nur einmal meldet.

04

Schnellstart

Ihren ersten Hive in Betrieb zu nehmen dauert unter einer Minute, wenn Sie die vorgeschlagenen Einstellungen übernehmen.

  1. Wählen Sie in der Seitenleiste HIVE Tracking und klicken Sie dann auf + New Hive.
  2. Wählen Sie die Tags aus, die Sie gruppieren möchten (zwischen 2 und 5). Tags, die bereits zu einem anderen Hive gehören, sind nicht verfügbar.
  3. Geben Sie dem Hive einen Namen — etwas Beschreibendes wie Travel Kit oder Workshop Tools.
  4. HIVE analysiert die jüngsten Bewegungen Ihrer Tags und schlägt ein Mobilitätsprofil sowie eine Abstandsschwelle vor. Zeigt das Abzeichen High Confidence, klicken Sie auf Use Suggested Settings und sind fertig.
  5. Andernfalls klicken Sie auf Review Settings, um den Assistenten mit 3 Fragen zu durchlaufen.

Ihr Hive beginnt sofort mit der Überwachung. Es gibt eine kurze Aufwärmphase von 5 bis 10 Minuten, in der HIVE den Ausgangszustand bestimmt; danach werden Warnungen normal ausgelöst. Solange Ihre Gegenstände gemeinsam unterwegs sind, bleiben Überschreitungsartefakte „vermutet“ und lösen sich auf, sobald Sie zur Ruhe kommen.

→ Tipp

Wenn Sie HIVE schon einmal verwendet haben, merkt sich der Assistent Ihre letzte Konfiguration. Einen Hive mit ähnlichen Einstellungen neu anzulegen kostet nur wenige Klicks.

05

Grundbegriffe

Gruppendurchmesser

Der größte Abstand zwischen zwei beliebigen Tags Ihres Hives. Hat Ihr Hive 5 Tags, misst HIVE alle 10 paarweisen Abstände und meldet den größten. Die Gruppe gilt als „zusammen“, solange der Durchmesser unter Ihrer Schwelle bleibt.

Abstandsschwelle

Der maximale Gruppendurchmesser, den Sie tolerieren, bevor eine Warnung ausgelöst wird. Je Hive konfigurierbar und auf jedem Bildschirm neben dem aktuellen Durchmesser angezeigt. Die Standardwerte reichen je nach Profilwahl von 150 m (unbewegliche Güter) bis 1000 m (mobile Güter oder Güter im Transit).

Mobilitätsprofil

Eine gebündelte Voreinstellung, die steuert, wie HIVE die Positionsdaten Ihrer Tags interpretiert. Sie wirkt sich auf Aktualitätsfenster, Warnempfindlichkeit, das Fenster für zeitliche Kohärenz und die Bestätigungsanforderungen aus. Drei Optionen: Stationary, Slow und Mobile.

Aktualitätsstufe

Jedes Tag wird danach eingestuft, wie kürzlich es gemeldet hat. Tags rutschen durch die Stufen, während sie stumm bleiben: FRESH RECENT STALE LOST. Nur Fresh- und Recent-Tags gehen in die Warnauswertung ein.

Zeitliche Kohärenz NEW v2.0

Gibt an, ob zwei Positionsmeldungen zeitlich nah genug beieinander erfasst wurden, um sinnvoll verglichen werden zu können. HIVE bestätigt eine Überschreitung nur aus zeitlich kohärenten Positionen, damit eine gemeinsam reisende Gruppe (deren Meldungen sich über eine Fahrt verteilen) nicht wie eine Trennung aussieht. Der zulässige Zeitabstand wird je Mobilitätsprofil abgestimmt.

Hive-Lebenszyklus

Jeder Hive hat ab dem Zeitpunkt seiner Erstellung eine operative Lebensdauer von 60 Tagen. Danach wandert er in ein 60-Tage-Archiv, in dem Sie seine Historie einsehen können, das aber nicht mehr überwacht. Nach Ablauf der Archivfrist werden die Daten gelöscht, sofern Sie nicht eingreifen.

06

Einrichtungsassistent

Der Assistent ist ein Ablauf mit 3 Fragen, der Sekunden dauern soll, nicht Minuten. Er füllt jede Antwort anhand der jüngsten Aktivität Ihrer Tags vor, sodass die meisten Nutzer einfach bestätigen und fortfahren können.

Frage 1 — Was verfolgen Sie?

Ein aussagekräftiger Name für den Hive. Optional, aber empfehlenswert: Warnungen und Historie beziehen sich auf diesen Namen, deshalb ist etwas Konkretes wie Travel Kit besser als Hive 4.

Frage 2 — Wie stark bewegen sich diese Gegenstände?

Die Wahl des Mobilitätsprofils. HIVE wählt es anhand der Bewegungen Ihrer Tags in den letzten Wochen vor und kennzeichnet es mit einem SUGGESTED Abzeichen. Drei Optionen stehen zur Wahl:

  • They stay put — Gegenstände, die sich normalerweise nicht von ihrem Platz bewegen sollten. Werkzeuge in einer Werkstatt, Geräte auf einem Hof, Instrumente im Labor.
  • They move occasionally — Gegenstände, die sich manchmal und langsam bewegen. Vieh, abgestellte Fahrzeuge, Mobilitätshilfen, Gepäck während einer Reise. HIVE erwartet lange Ruhephasen mit gelegentlicher Bewegung.
  • They're often on the move — Gegenstände, die Sie täglich bei sich tragen oder die unterwegs sind. Persönliche Dinge, Lieferpakete, Flottenausrüstung. HIVE ist am genauesten, wenn diese Gegenstände ruhen; während sie gemeinsam unterwegs sind, bleiben Überschreitungsartefakte „vermutet“ und lösen sich bei Ankunft auf.

Siehe Mobilitätsprofile für alle Einzelheiten.

Frage 3 — Wie nah sollen sie beieinanderbleiben?

Die Abstandsschwelle. Wählen Sie aus den vorgegebenen Werten (150 m, 250 m, 450 m, 750 m, 1000 m) oder geben Sie einen eigenen Wert ein. Der Standardwert passt zum gewählten Mobilitätsprofil.

→ Expressweg

Ist HIVE seinen Vorschlägen gegenüber sehr zuversichtlich (typischerweise, wenn Ihre Tags mindestens 7 Tage Historie haben), erscheint oben im Assistenten eine Express-Karte. Klicken Sie auf Use Suggested Settings, um die Fragen ganz zu überspringen.

07

Mobilitätsprofile

Mobilitätsprofile sind die wichtigste Konfigurationsentscheidung. Sie sagen HIVE, welche Art von Gut Sie überwachen, und das beeinflusst nahezu jeden Aspekt der Warnauswertung — einschließlich des Fensters für zeitliche Kohärenz, das die veralterungsbewusste Auswertung nutzt.

ProfilAm besten fürStandardschwelleKohärenzfenster
Stationary Werkzeuge, Geräte, Instrumente — Güter, die sich normalerweise nicht bewegen sollten 150 m 30 Min.
Slow Vieh, abgestellte Fahrzeuge, Mobilitätshilfen, Gepäck während einer Reise 450 m 10 Min.
Mobile Persönliche Gegenstände, gemeinsam genutzte Ausrüstung, Kurierpakete, Flottengüter, Fahrzeuge auf der Straße 1000 m 5 Min.

Was Profile tatsächlich verändern

Die Wahl eines Profils setzt mehrere Parameter auf einmal. Mit zunehmender Mobilität verkürzen sich die Aktualitätsfenster (ältere Positionen verlieren schneller an Verlässlichkeit), die Bestätigungsanforderungen werden strenger, die Rauschfilter weiter, und das Fenster für zeitliche Kohärenz wird enger (schneller bewegte Güter verlangen also enger abgestimmte Meldungen, bevor eine Überschreitung als belastbar gilt).

Das Profil Mobile deckt eine große Bandbreite ab — von persönlichen Gegenständen, die meist ruhen, bis zu Lieferpaketen im aktiven Transit. HIVE ist am genauesten, wenn diese Gegenstände ruhen; während sie gemeinsam unterwegs sind, bleiben Überschreitungsartefakte „vermutet“ statt bestätigt und lösen sich auf, sobald der Hive zur Ruhe kommt.

Die Spalte Standardschwelle zeigt den Ausgangswert jedes Profils, kalibriert auf eine typische Meldefrequenz von 5 bis 10 Minuten. Sie können die Schwelle für Ihren Anwendungsfall bei der Einrichtung oder später in den Hive-Einstellungen nach oben oder unten anpassen.

→ Das falsche Profil wählen

Erzeugt Ihr Hive dauerhaft zu viele Fehlalarme oder übersieht er echte, passt vermutlich das Profil nicht. HIVE weist mit einem dezenten Hinweis darauf hin, wenn es das erkennt. Sie können das Profil während der Laufzeit ändern — siehe Löschen und neu anlegen.

08

Hive-Liste

Der Hauptbildschirm von HIVE zeigt alle Ihre aktiven Hives auf einen Blick. Jede Karte nennt den Namen des Hives, den aktuellen Status, den Gruppendurchmesser im Verhältnis zur Schwelle, die Aktualitäts-Kacheln der Tags, den Ausreißer (sofern vorhanden) und die Lebenszyklus-Uhr.

Status auf einen Blick

Der farbige obere Rand zeigt den Zustand sofort an:

  • GRÜN — Alle Tags sind beisammen, der Hive ist OK
  • BERNSTEIN — Teildaten, Aktualitätsprobleme oder eine vermutete (unbestätigte) Überschreitung
  • ROT — Aktive Überschreitung; ein oder mehrere Tags haben sich getrennt

Tag-Kacheln

Die kleinen nummerierten Quadrate stehen für jedes Tag im Hive, farblich nach Aktualität codiert:

01
02
03
04
05

Ein roter Punkt in der Ecke einer Kachel zeigt an, dass dieses Tag der aktuelle Ausreißer ist.

Aktionen auf der Karte

Jede Karte bietet vier Schnellaktionen:

  • Edit — Hive-Einstellungen öffnen (Mobilitätsprofil, Schwelle)
  • Map — Zur Live-Positionsansicht springen
  • History — Frühere Warnungen und Auswertungen ansehen
  • Delete — Hive ins Archiv verschieben (60 Tage wiederherstellbar)
09

Detailansicht

Ein Klick auf eine Hive-Karte öffnet deren Detailansicht — der ausführlichste Arbeitsbereich, um Zustand und Historie eines Hives zu verstehen.

Live-Positionskarte

Zeigt die jeweils jüngste Position jedes Tags im Verhältnis zu den anderen. Der gestrichelte Kreis markiert Ihre Abstandsschwelle. Verbindungslinien stellen die paarweisen Abstände dar — grüne Linien für Paare innerhalb der Grenze, rot gestrichelte Linien für Paare oberhalb der Schwelle, die zum Ausreißer führen.

Durchmesseranzeige

Eine numerische Live-Anzeige des aktuellen Gruppendurchmessers, daneben ein waagerechtes Balkendiagramm mit der Schwellenmarkierung. Überschreitet der Balken die Markierung und ist die Trennung durch zeitlich abgestimmte Meldungen bestätigt, liegt eine Überschreitung vor. Ein Durchmesser, der nur wegen zeitlich nicht zusammenpassender Meldungen über der Schwelle liegt (typisch unterwegs), erscheint als vermutete und nicht als bestätigte Überschreitung.

Tag-Tabelle

Eine Zeile je Tag mit ID, Name, Zeitpunkt der letzten Sichtung, Abstand zum Gruppenmittelpunkt und Rolle (Kern oder Ausreißer). Nach jeder Spalte sortierbar. Stale- oder Lost-Tags werden abgeblendet dargestellt.

Seitenpanels

Die rechte Spalte bündelt mehrere Panels:

  • Active Alert — Details zur aktuellen Überschreitung (sofern vorhanden), mit Ursache und Anzahl der Bestätigungen
  • Configuration — Aktuelles Mobilitätsprofil, Schwelle, Aktualitätsfenster und weitere Parameter
  • Lifecycle — Verbleibende Tage auf der 60-Tage-Uhr, mit einer Schnellschaltfläche Recreate Hive
  • Recent Activity — Zeitleiste der Auswertungen, Überschreitungsereignisse und Warnungen der letzten 24 Stunden
10

Warnungen und Überschreitungen

HIVE gibt je nach Datenqualität und Art der Änderung unterschiedliche Warnungstypen aus. Wer den Unterschied kennt, kann angemessen reagieren.

WarnungstypBedeutungMaßnahme
Confirmed Breach Mehrere frische Meldungen zeigen, dass der Hive geteilt ist (nur Stationary) Prüfen und handeln — das verlässlichste Signal
Suspected Breach Eine frische Meldung deutet eine Überschreitung an, Bestätigung steht aus Auf Eskalation achten; kann sich von selbst erledigen
Lost Contact Ein Tag ist über die Lost-Schwelle hinaus verstummt Batterie und physischen Zustand des Tags prüfen
Partially Observable Zu viele Tags sind veraltet für eine belastbare Auswertung Erledigt sich oft von selbst, sobald wieder Daten eintreffen
Breach Cleared Der Hive ist in den Zustand OK zurückgekehrt Informativ — bestätigt, dass das Problem behoben ist
Resolved by Transit NEW Eine aktive Überschreitung wurde aufgehoben, weil der Hive in Bewegung geriet Informativ — die Überwachung wird beim Anhalten fortgesetzt

Warum Warnungen Zeit brauchen können

Da Tag-Positionen aus Crowdsourced-Quellen stammen, hängt die Warnlatenz davon ab, wie oft Telefone in der Nähe vorbeikommen. In städtischen Gebieten werden Überschreitungen typischerweise binnen 3 bis 8 Minuten bestätigt. In ländlichen oder wenig frequentierten Gegenden kann es 15 bis 30 Minuten oder länger dauern. Das ist keine Systemverzögerung, sondern die Zeit, die nötig ist, um genügend belastbare Hinweise zu sammeln.

→ Ehrlich mit Unsicherheit

HIVE meldet lieber „Datenqualität eingeschränkt“, als Warnungen mit geringer Aussagekraft auszulösen. Sehen Sie diesen Hinweis, kann der Hive nicht sicher sagen, was geschieht — meist, weil Tags verstummt sind oder ihre Meldungen zeitlich nicht ausreichend zusammenpassen, und nicht, weil etwas nicht stimmt.

11

Aktualität der Tags

Die Aktualität eines Tags gibt an, wie aktuell die vorliegende Position ist. Die Schwellen unterscheiden sich je nach Mobilitätsprofil — die Position eines schnell bewegten Guts altert schneller als die eines ruhenden.

StufeStationarySlowMobile
Fresh<30 Min.<20 Min.<15 Min.
Recent30 Min. – 4 Std.20 Min. – 2 Std.15 Min. – 1 Std.
Stale4–24 Std.2–8 Std.1–4 Std.
Lost>24 Std.>8 Std.>2 Std.

In die Überschreitungsauswertung gehen nur Fresh- und Recent-Tags ein. Stale-Tags werden ausgeschlossen, aber weiterhin in der Oberfläche angezeigt. Lost-Tags lösen eine eigene Lost-Contact-Warnung aus.

12

Laufzeit von 60 Tagen

Jeder Hive hat ab dem Zeitpunkt der Erstellung eine feste operative Laufzeit von 60 Tagen. Das ist keine Einschränkung, sondern ein Ordnungsmechanismus, der Ihre Hive-Liste auf das Wesentliche konzentriert. Nach Ablauf wandert der Hive in ein 60-Tage-Archiv, in dem Sie die Historie weiterhin einsehen können.

Einen Hive neu anlegen

Die Schaltfläche Recreate Hive (sichtbar auf der Detailseite des Hives und in Ablaufbenachrichtigungen) öffnet einen neuen Assistenten, der mit Ihrer aktuellen Konfiguration und Ihren Tags vorbelegt ist. Ein Klick, und Ihre Überwachung läuft ohne Unterbrechung weiter.

→ Warum eine Grenze von 60 Tagen?

Hives sammeln sich an. Ohne Lebenszyklus verstopfen aufgegebene Hives die Oberfläche und belegen dauerhaft Tag-Plätze. Die 60-Tage-Grenze erzwingt eine regelmäßige Durchsicht: Behalten Sie, was zählt, und lassen Sie den Rest ablaufen.

13

Löschen und neu anlegen

Die Zusammensetzung eines Hives ist bei der Erstellung festgelegt. Um ein Tag hinzuzufügen oder zu entfernen, müssen Sie den Hive löschen und einen neuen anlegen. Das klingt einschränkend, ist in der Praxis aber schneller als Bearbeiten — der Ablauf zum Neuanlegen füllt alles vor.

Zwei Arten des Löschens

AktionErgebnisUmkehrbar?
Delete Hive wandert ins Archiv · Historie 60 Tage aufbewahrt Ja, über Recreate
Permanently Delete Alle Daten sofort entfernt · kein Archiv Nein

Beide Optionen werden in der üblichen Löschbestätigung angeboten. Delete ist die wiederherstellbare Wahl; bei Permanently Delete müssen Sie zur Bestätigung den Namen des Hives eintippen.

Der Ablauf zum Neuanlegen

Wenn Sie einen Hive löschen und anschließend neu anlegen, öffnet sich der Assistent vorbelegt mit Konfiguration und Tags des gelöschten Hives. Sie können alles anpassen — Tags hinzufügen oder entfernen, die Schwelle ändern, das Mobilitätsprofil wechseln — und bestätigen. Der neue Hive startet frisch, ohne übernommene Historie.

→ Ein Tag, ein Hive

Ein Tag kann jeweils nur zu einem Hive gehören. Versuchen Sie, ein Tag hinzuzufügen, das bereits in einem anderen Hive ist, wird Ihnen angezeigt, in welchem — löschen Sie diesen zuerst, um das Tag freizugeben.

14

Archiv

Die Archivansicht zeigt alle Ihre früheren Hives — gelöschte wie abgelaufene — innerhalb ihrer 60-tägigen Aufbewahrungsfrist. Jeder archivierte Hive behält seine vollständige Warnhistorie, sein Auswertungsprotokoll und seinen Konfigurationsstand.

Was Sie im Archiv tun können

  • Ansehen früherer Warnungen, Überschreitungen und Zeitleisten
  • Neu anlegen auf Basis der Konfiguration eines archivierten Hives
  • Endgültig löschen eines archivierten Hives, um dessen Daten sofort zu entfernen

Automatisches Löschen

60 Tage nach Eintritt ins Archiv werden Hives automatisch gelöscht. Auf jeder archivierten Karte sehen Sie eine Countdown-Uhr.

Fehlerbehebung

Ich bekomme bei Autofahrten weniger falsche Überschreitungswarnungen — ist etwas kaputt?

Nein — das ist die veralterungsbewusste Auswertung aus v2.0, die genau so arbeiten soll. Früher löste HIVE falsche Überschreitungen aus, sobald Sie mit Ihrem Hive im Auto fuhren, weil es Positionsmeldungen von verschiedenen Punkten der Strecke verglich. HIVE weigert sich nun, eine Überschreitung aus zeitlich nicht zusammenpassenden Meldungen zu bestätigen, sodass eine Fahrt höchstens eine kurze „vermutete“ Überschreitung erzeugt, die sich von selbst auflöst. Echte Trennungen lösen weiterhin aus, sobald Sie angehalten haben.

Ich habe kurz „vermutete Überschreitung“ gesehen, aber keine Warnung, und alles war beisammen — was war das?

Mit hoher Wahrscheinlichkeit eine einzelne verirrte GPS-Messung. Crowdsourced-Positionen stammen von vorbeikommenden Telefonen, und gelegentlich meldet eines den Standort eines Tags mit schlechter Genauigkeit und verortet es kurz weit weg von der Gruppe. Genau dafür ist die Beständigkeitsprüfung von HIVE gedacht: Eine einmalige Fehlmessung hält nicht lange genug an, um bestätigt zu werden, bleibt also „vermutet“ und verschwindet, sobald die nächste gute Meldung eintrifft. Eine Fehlwarnung erhalten Sie dadurch nicht.

Ich sehe unterwegs „vermutete Überschreitung“ und dann „aufgehoben“ — was ist das?

Das ist die veralterungsbewusste Auswertung bei der Arbeit. Während Ihre Gegenstände gemeinsam unterwegs sind, entstehen ihre Positionsmeldungen an verschiedenen Punkten der Strecke, was kurzzeitig wie eine Trennung aussehen kann. HIVE kennzeichnet dies als vermutete Überschreitung, statt sie zu bestätigen, und hebt sie automatisch auf, sobald frische, zeitlich abgestimmte Meldungen die Gruppe wieder beisammen zeigen. Aus normalem Unterwegssein entsteht keine Warnung über eine bestätigte Überschreitung.

Mein Hive zeigt „Partial Data“ — stimmt etwas nicht?

Meist nicht. „Partial Data“ bedeutet, dass zu viele Tags des Hives nicht kürzlich gemeldet haben, als dass HIVE belastbar auswerten könnte. Das ist in wenig frequentierten Gegenden üblich, wo selten Telefone vorbeikommen. Prüfen Sie die Aktualitäts-Kacheln: Sind die meisten bernsteinfarben oder rot, befindet sich der Hive in einer ruhigen Gegend.

Ich erhalte zu viele Warnungen (im Stand)

Drei Dinge, die Sie prüfen sollten:

  • Ist Ihre Abstandsschwelle angemessen? Erhöhen Sie sie, wenn Sie Fehlalarme bekommen — der Standardwert für das Profil Mobile liegt bei 1000 m
  • Passt Ihr Mobilitätsprofil? Ein stationäres Profil auf tatsächlich mobilen Gütern warnt ununterbrochen
  • Sind die Tag-Positionen verrauscht? Ein Telefon-GPS geringer Qualität kann 10 bis 50 m Schwankung erzeugen

Ich erhalte zu wenige Warnungen

Entweder ist Ihre Schwelle zu großzügig, oder Ihre Tags melden zu selten. Ziehen Sie die Schwelle enger und beobachten Sie eine Woche lang. Beachten Sie: Eine echte Trennung wird erst bestätigt, wenn frische, zeitlich abgestimmte Meldungen sie belegen — melden Ihre Tags sehr selten, kann sich die Bestätigung verzögern, bis genügend kohärente Meldungen vorliegen.

Ein Tag, das ich verwenden möchte, ist angeblich „in another hive“

Jedes Tag kann jeweils nur zu einem Hive gehören. Die Oberfläche zeigt, in welchem Hive es sich derzeit befindet — löschen Sie diesen Hive (oder löschen Sie ihn endgültig), um das Tag freizugeben.

Ich habe die Schwelle geändert, aber alte Warnungen wurden nicht aktualisiert

Konfigurationsänderungen gelten nur für künftige Auswertungen — historische Warnungen bleiben so, wie sie ursprünglich bewertet wurden. Das ist beabsichtigt: So bleibt Ihre Warnhistorie aussagekräftig und nachvollziehbar.

FAQ

Wie viele Tags kann ein Hive enthalten?

Derzeit 2 bis 5. Größere Gruppen stehen auf der Roadmap.

Kann ein Tag zu mehreren Hives gehören?

Nein. Ein Tag, ein Hive zu einem gegebenen Zeitpunkt.

Gibt es eine Obergrenze für die Anzahl meiner Hives?

Nein, Sie können beliebig viele anlegen, solange Sie für jeden genügend freie Tags haben.

Kann ich die Tags eines Hives nach der Erstellung ändern?

Nein. Die Zusammensetzung ist bei der Erstellung festgelegt. Um sie zu ändern, löschen Sie den Hive und legen ihn neu an — der Ablauf dafür geht schnell.

Kann ich die Laufzeit eines Hives über 60 Tage hinaus verlängern?

Nicht direkt, aber Sie können den Hive mit derselben Konfiguration neu anlegen und so einen neuen 60-Tage-Zyklus starten. Das dauert etwa 10 Sekunden.

Funktioniert HIVE mit meinen vorhandenen Tags?

Ja. Jedes iBeacon- oder Eddystone-Tag, das in Beacon Telematics registriert ist, lässt sich einem Hive hinzufügen.

Wie schnell treffen Warnungen ein?

Das hängt davon ab, wie häufig Ihre Tags melden. In städtischen Gebieten treffen Warnungen typischerweise innerhalb von 3 bis 8 Minuten nach einer echten Überschreitung ein. In ländlichen Gegenden kann es 15 bis 30 Minuten dauern. Das System wartet auf die Bestätigung, um Fehlalarme zu vermeiden.

Verpasse ich eine echte Trennung, während mein Hive in Bewegung ist? v2.0

Eine echte Trennung wird bestätigt, sobald frische, zeitlich abgestimmte Meldungen sie belegen — das ist meist kurz nach dem Anhalten der Fall, wenn sich die Meldungen stabilisieren. Unterwegs kann eine echte Trennung zunächst als vermutete Überschreitung erscheinen. Jede bestätigte Überschreitung löst normal aus. Für die meisten Nutzer, deren Gegenstände mit ihnen reisen, lautet die entscheidende Frage „ist alles mit mir angekommen?“ — und die ist beantwortet, sobald Sie zur Ruhe kommen.

Was passiert, wenn die Batterie eines Tags leer ist?

Das Tag verstummt und wandert mit der Zeit über Stale zu Lost. Sie erhalten für dieses Tag eine Lost-Contact-Warnung. Ersetzen Sie das Tag und fügen Sie es erneut hinzu — beachten Sie, dass Sie den Hive löschen und neu anlegen müssen, um das Tag auszutauschen.

Kann ich die Historie eines Hives exportieren?

Eine Exportfunktion steht auf der Roadmap. Vorerst behalten archivierte Hives ihre vollständige Historie 60 Tage lang, einsehbar in der Oberfläche.

Was ist der Unterschied zwischen Delete und Permanently Delete?

Delete verschiebt den Hive in ein 60-Tage-Archiv, in dem Sie die Historie weiterhin einsehen und ihn neu anlegen können. Permanently Delete entfernt alle Daten sofort und lässt sich nicht rückgängig machen.
