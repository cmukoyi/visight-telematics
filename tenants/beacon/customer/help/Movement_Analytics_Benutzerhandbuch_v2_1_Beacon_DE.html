Movement Analytics

Verwandeln Sie einen Strom von Positionsmeldungen in Fahrten, die sich tatsächlich lesen lassen — wohin ein Asset unterwegs war, wo es angehalten hat, wie lange und wie weit es gefahren ist. Entwickelt für Fahrzeuge, Maschinen, Pakete und jedes bewegte Asset, das getrackt wird.

01

Überblick

Ihre Tags melden laufend Positionen — oft im Minuten- oder Zwei-Minuten-Takt. Für sich genommen sind diese Meldungen nur eine Punktwolke. Movement Analytics liest sie der Reihe nach und erschließt daraus die Geschichte dahinter: Das Asset stand hier drei Stunden, fuhr dann 10,5 km, hielt zwanzig Minuten und fuhr anschließend weitere 4 km.

Das Ergebnis ist eine Fahrt: ein Beginn, eine oder mehrere Etappen, die Stopps dazwischen und ein Ende. Jede Fahrt trägt eine Gesamtdistanz und -dauer, und jede Etappe wird auf der Karte gezeichnet, sodass Sie die gefahrene Route sehen.

Movement Analytics arbeitet mit den Positionsdaten, die Ihre Assets in Beacon Telematics ohnehin schon melden. Keine zusätzliche Hardware, keine separate Gerätekonfiguration — Sie aktivieren das Fahrten-Abonnement am Asset, und ab diesem Zeitpunkt werden Fahrten aufgebaut.

→ Auf einen Blick

Fahrten automatisch aus Positionsmeldungen aufgebaut · Etappen und Stopps getrennt klassifiziert · Distanz und Dauer je Fahrt und je Etappe · Vollständige Route auf der Karte gezeichnet · Rohpositionen parallel verfügbar · Abonnement pro Asset, vom Administrator gesteuert.

02

Funktionsweise

Movement Analytics verarbeitet die Positionen jedes Assets in zeitlicher Reihenfolge und verfolgt dabei eine einzige Frage: Steht dieses Asset gerade still oder ist es in Bewegung?

Steht
→
In Bewegung
→
Stabilisierung
→
Steht

Solange ein Asset steht, sammeln sich seine Meldungen um einen Ort. Movement Analytics hält für diese Ansammlung eine gemittelte Position vor — den Ankerpunkt — und verfeinert sie mit jeder neuen Meldung. Kleine Schwankungen in den Positionsdaten verschieben den Ankerpunkt kaum, und genau das verhindert, dass ein geparktes Fahrzeug scheinbar über den Parkplatz driftet.

Fällt eine Meldung deutlich außerhalb dieser Ansammlung, ist das Asset losgefahren und eine Etappe wird eröffnet. Jede weitere Meldung wird der Etappe hinzugefügt und baut so die Route auf.

Sobald sich die Meldungen an einem neuen Ort erneut sammeln und dort bleiben, wertet Movement Analytics dies als Ankunft, schließt die Etappe an dieser Stelle ab und beginnt einen neuen Stopp. Vor der endgültigen Festlegung wird eine kurze Stabilisierungszeit abgewartet — so wird ein Halt an der Ampel nicht als Stopp erfasst.

Schließlich dienen Stopps dazu, die Zeitachse in Fahrten zu unterteilen. Ein kurzer Stopp ist ein Zwischenpunkt innerhalb einer Fahrt. Ein langer beendet die Fahrt — die nächste Abfahrt beginnt eine neue.

→ Warum manche kurzen Bewegungen nicht erfasst werden

Eine Etappe muss echte Bewegung abbilden, nicht Positionsrauschen. Bewegung, die sich nicht weit genug vom Ausgangspunkt entfernt, wird verworfen statt als Fahrt erfasst. Das ist beabsichtigt: Andernfalls würde ein stehendes Asset mit verrauschten Meldungen täglich Dutzende bedeutungsloser Ein-Minuten-„Fahrten“ erzeugen.

03

Schnellstart

Ein Asset auf Fahrten umzustellen dauert etwa dreißig Sekunden — Administratorrechte vorausgesetzt.

  1. Öffnen Sie Assets und bearbeiten Sie das Asset, das Sie verfolgen möchten. Der Dialog Edit Tag öffnet sich.
  2. Setzen Sie das Häkchen bei Enable Advanced Trip Analysis. Ist das Kontrollkästchen ausgegraut, fehlen Ihnen die Administratorrechte — bitten Sie einen Systemadministrator, die Funktion zu aktivieren.
  3. Klicken Sie auf Save Changes. Ab dem nächsten Positionsabruf werden Fahrten aufgebaut.
  4. Wechseln Sie zu Movement Analytics. Ihr Asset erscheint nun links in der Asset-Liste.
  5. Wählen Sie es aus, legen Sie einen Zeitraum fest, und die Fahrten erscheinen im rechten Bereich, mit der Route auf der Karte.

Über das Kontrollkästchen hinaus gibt es pro Asset nichts einzustellen. Die Erkennungsparameter gelten plattformweit und werden zentral abgestimmt.

→ Erwarten Sie nicht die Fahrten von gestern

Advanced Trip Analysis wirkt nur vorwärts. Eine Aktivierung jetzt baut keine Fahrten aus bereits erfassten Positionen auf. Wenn Sie für ein Asset Historie benötigen, aktivieren Sie die Funktion vor dem Zeitraum, der Sie interessiert.

Sollen historische Daten für einen bereits vergangenen Zeitraum nachträglich verarbeitet werden, richten Sie eine Anfrage an Ihren Administrator, um das weitere Vorgehen abzustimmen.

04

Grundbegriffe

Position

Eine einzelne Standortmeldung eines Tags mit Zeitstempel. Positionen sind die Rohdaten — alles andere wird daraus abgeleitet. Sie können sie direkt in der Registerkarte Positions einsehen.

Etappe

Ein zusammenhängender Bewegungsabschnitt zwischen zwei Stopps. Eine Etappe hat eine Startzeit, eine Endzeit, eine Distanz und eine Route, die aus den unterwegs erfassten Positionen gezeichnet wird. Etappen werden auf der Karte blau dargestellt.

Stopp

Ein Zeitraum, in dem das Asset an einem Ort geblieben ist. Jeder Stopp hält fest, wann er begann, wann er endete, wie lange er dauerte (Standzeit) und wie viele Positionen zu ihm beigetragen haben. Stopps erscheinen als bernsteinfarbene Marker.

Ankerpunkt

Die gemittelte Position eines Stopps, die mit jeder weiteren Meldung verfeinert wird. Der Ankerpunkt ist das, was der Marker auf der Karte zeigt, und er ist der Bezugspunkt, an dem neue Meldungen gemessen werden, um zu entscheiden, ob das Asset losgefahren ist.

Standzeit

Wie lange ein Stopp gedauert hat. Die Standzeit entscheidet, ob ein Stopp ein Zwischenpunkt innerhalb einer Fahrt ist oder deren Ende.

Fahrt

Ein Beginn, eine Abfolge von Etappen und kurzen Stopps, und ein Ende. Die Distanz einer Fahrt ist die Summe ihrer Etappen. Fahrten sind im Bereich nummeriert und lassen sich aufklappen, um ihren inneren Aufbau zu zeigen.

Inaktiv

Die Lücke zwischen zwei Fahrten, in der Zeitachse als Chip dargestellt — zum Beispiel 9 Std. 26 Min. inaktiv. Dies ist der lange Stopp, der sie getrennt hat.

05

Advanced Trip Analysis

Admin

Movement Analytics wird pro Asset über das Kontrollkästchen Enable Advanced Trip Analysis aktiviert. Jedes Asset der Plattform zu verarbeiten wäre Verschwendung — die meisten benötigen keine Fahrtenrekonstruktion —, deshalb erfolgt die Aktivierung gezielt.

Wo Sie es finden

Das Kontrollkästchen Enable Advanced Trip Analysis befindet sich im Dialog Edit Tag am Asset selbst — erreichbar, indem Sie ein Asset aus Assets heraus bearbeiten. Es ist weder eine Massenaktion noch ein eigener Verwaltungsbildschirm.

Wer es ändern darf

RolleSieht die EinstellungDarf sie ändern
SystemadministratorJaJA
Alle anderen BenutzertypenJa — ausgegrautNEIN

Nicht-Administratoren sehen die Einstellung schreibgeschützt, statt dass sie ausgeblendet wird. Das ist Absicht: So erkennt jeder auf einen Blick, ob ein Asset abonniert ist, ohne nachfragen zu müssen.

Was beim Aktivieren passiert

Der Fahrtenaufbau startet mit dem nächsten Positionsabruf. Bereits gespeicherte Positionen werden nicht erneut verarbeitet. Entfernen Sie das Häkchen, bleiben vorhandene Fahrten sichtbar, es entstehen jedoch keine neuen.

Wenn Sie historische Daten benötigen

Die erneute Verarbeitung von Positionen, die vor der Aktivierung von Advanced Trip Analysis erfasst wurden, lässt sich nicht vom Asset aus anstoßen. Sollen Fahrten für einen bereits vergangenen Zeitraum aufgebaut werden, richten Sie eine Anfrage an Ihren Administrator, um das weitere Vorgehen abzustimmen.

→ Die Asset-Liste ist gefiltert

Der Bildschirm Movement Analytics listet nur Assets mit aktiviertem Advanced Trip Analysis. Fehlt ein Asset, das Sie erwarten, ist das Kontrollkästchen nicht gesetzt — das ist das Erste, was Sie prüfen sollten.

Zeitraum und Filter

Der linke Bereich steuert, welches Asset Sie betrachten und über welchen Zeitraum.

Zeitraum

Wählen Sie zwischen Today, Yesterday, Last 7 days, Last 30 days oder Custom für einen frei gewählten Zeitraum. Die Kopfzeile des Fahrtenbereichs zeigt Ihnen, wie viele Fahrten in den gewählten Zeitraum fallen.

Status

Zähler am oberen Rand zeigen, wie viele Assets Total, Active, Idle und Offline sind. Klicken Sie auf einen davon, um die Liste zu filtern.

Asset-Typ

Weitere Chips filtern nach Kategorie — zum Beispiel New Tags, Parcels, QR Code. Welche Chips erscheinen, hängt davon ab, was in Ihrem Konto registriert ist.

Sortierung

Die Asset-Liste ist standardmäßig nach letzter Meldung sortiert, sodass die zuletzt aktiven Assets oben stehen. Jede Zeile zeigt, wie lange die letzte Meldung des Assets zurückliegt und, sofern verfügbar, den Batteriestand.

08

Eine Fahrt lesen

Fahrten sind nach Tagen gruppiert, die neueste zuerst, und innerhalb des gewählten Zeitraums nummeriert. Die zusammengeklappte Zeile zeigt das Wesentliche: Zeitspanne, Gesamtdistanz sowie die Anzahl der Etappen und Stopps.

Klappen Sie eine Fahrt auf, wird ihr Aufbau der Reihe nach aufgelistet:

EintragBedeutung
STARTBeginn der Fahrt — der Moment, in dem das Asset losgefahren ist
LEGEin Bewegungsabschnitt mit Distanz und Dauer
STATIONARYEin Stopp innerhalb der Fahrt, mit seiner Standzeit
ENDEnde der Fahrt

Zwischen den Fahrten sehen Sie einen idle-Chip, der die Lücke anzeigt — den langen Stopp, der sie getrennt hat. Beginnt ein Tag mit einem langen Inaktivitäts-Chip, bedeutet das schlicht, dass das Asset über Nacht geparkt war.

Distanzen und Zeiten

Die Distanz einer Fahrt ist die Summe ihrer Etappen; Stopps tragen nichts bei. Zeiten werden in Ihrer lokalen Zeitzone angezeigt. Die Distanzeinheit folgt Ihrer Kontoeinstellung — Kilometer oder Meilen.

09

Etappen

Eine Etappe wird aus den Positionen gezeichnet, die gemeldet wurden, während das Asset in Bewegung war. Ihre Form ist daher nur so detailliert, wie die Meldungen häufig waren.

Warum manche Etappen wie gerade Linien aussehen

Hat ein Asset während einer Fahrt zehnmal gemeldet, folgt die Etappe der Straße recht genau. Hat es dreimal gemeldet, erhalten Sie ein Dreieck. Beides sind zutreffende Darstellungen dessen, was tatsächlich erfasst wurde — Movement Analytics zeichnet, was vorliegt, und erfindet weder Zwischenpunkte noch legt es Routen auf den Straßenverlauf.

Die Meldehäufigkeit hängt vom Positionierungsverfahren und der Umgebung ab, weshalb zwei Assets im selben Fahrzeug unterschiedlich detaillierte Routen erzeugen können.

Rundfahrten

Eine Fahrt, die hinaus- und wieder zum Ausgangspunkt zurückführt, ist trotzdem eine Etappe, auch wenn Start- und Endpunkt dicht beieinanderliegen. Movement Analytics bewertet Etappen danach, wie weit sie tatsächlich zurückgelegt haben, nicht nur nach dem Abstand zwischen den Endpunkten.

→ Etappen enden an dem Stopp, den sie erreichen

Der letzte Punkt einer Etappe ist der Stopp, an dem sie ankommt. Die Routenlinie endet damit exakt auf dem Stopp-Marker und nicht kurz davor.

10

Stopps

Stopps werden als bernsteinfarbene Marker dargestellt. Liegen mehrere Stopps dicht beieinander, fasst die Karte sie zu einem einzelnen nummerierten Marker zusammen — die Zahl gibt an, wie viele dort übereinanderliegen.

Kurze Stopps und Fahrtunterbrechungen

Ein Stopp, der kürzer ist als der Schwellenwert für die Fahrtunterbrechung, ist ein Zwischenpunkt: Die Fahrt läuft danach weiter. Ein längerer Stopp beendet die Fahrt, und die nächste Abfahrt beginnt eine neue.

Deshalb kann dieselbe Zustellrunde an einem ruhigen Tag als eine Fahrt mit mehreren Stopps erscheinen und an einem vollen Tag als mehrere Fahrten — es hängt davon ab, wie lange das Asset an jeder Station gewartet hat.

Standzeit und Positionsanzahl

Jeder Stopp weist aus, wie lange er gedauert hat und wie viele Positionen ihn aufgebaut haben. Ein Stopp über mehrere Stunden hat typischerweise Dutzende Positionen angesammelt.

Laufende Stopps

Ein noch laufender Stopp erscheint bereits, während er andauert, mit einer Standzeit, die mit jeder neuen Meldung wächst. Sie müssen nicht warten, bis sich das Asset wieder bewegt, um den aktuellen Stopp zu sehen.

→ Alles auf einmal darstellen

Plot all über einen langen Zeitraum kann eine sehr dichte Karte erzeugen. Ist sie schwer zu lesen, engen Sie den Zeitraum ein, statt zu zoomen — die Kopfzeile des Bereichs zeigt, wie viele Fahrten einbezogen sind.

12

Registerkarte Positions

Die Registerkarte Positions zeigt die Rohmeldungen hinter den Fahrten — jede Position im gewählten Zeitraum, die neueste zuerst, mit Uhrzeit und aufgelöster Adresse.

Jede Zeile hat eine Schaltfläche zum Lokalisieren, die eine Nadel auf der Karte setzt. Remove all entfernt die gesetzten Nadeln.

Wann Sie sie nutzen

  • Auf die Minute genau prüfen, wann ein Asset an einem Ort war
  • Nachvollziehen, warum eine Etappe grob gezeichnet ist — die Positionsliste zeigt, wie oft das Asset tatsächlich gemeldet hat
  • Anwesenheit an einem Ort bestätigen, der keinen Stopp erzeugt hat
→ Positionen und Fahrten sind unterschiedliche Sichten

Die Registerkarte Positions listet alle Positionen des Zeitraums auf, auch solche, die außerhalb jeder Fahrt erfasst wurden. Sehen Sie auf der Karte dichte Punktwolken, durch die keine Etappe führt, stammen sie fast immer aus einer anderen Tageszeit — prüfen Sie die Zeitstempel, bevor Sie auf eine fehlende Fahrt schließen.

13

Datenqualität

Movement Analytics ist immer nur so gut wie die Positionen, die es erhält. Wer versteht, was diese beeinflusst, versteht das meiste von dem, was er sieht.

Meldehäufigkeit

Assets, die jede Minute melden, erzeugen detaillierte Routen und präzise Stoppzeiten. Assets, die alle fünfzehn Minuten melden, erzeugen grobe Routen, und kurze Stopps können ganz entfallen, weil es nicht genug Meldungen gab, um sie zu belegen.

Positionsgenauigkeit

Manche Positionierungsverfahren streuen prinzipbedingt um mehrere zehn Meter. Ein geparktes Asset kann dadurch innerhalb dieses Radius zu wandern scheinen. Die oben beschriebene Mittelung des Ankerpunkts soll das auffangen, sehr verrauschte Daten können dennoch zusätzliche Stopps erzeugen.

Lücken in der Abdeckung

Meldet sich ein Asset mitten in einer Fahrt längere Zeit nicht — etwa außerhalb der Netzabdeckung —, schließt Movement Analytics die Etappe an der letzten bekannten Position. Setzen die Meldungen andernorts wieder ein, beginnen ein neuer Stopp und eine neue Fahrt. Die Route über die Lücke hinweg wird nicht erraten.

Zwei Tags an einem Fahrzeug

Gemeinsam bewegte Assets sollten weitgehend übereinstimmende Fahrten erzeugen. Kleine Abweichungen bei Etappenzahl oder Distanz sind normal und rühren von unterschiedlichen Meldezeitpunkten her — besonders, wenn ein Stopp genau auf dem Schwellenwert der Fahrtunterbrechung liegt: Dann kann ein Tag eine Fahrt teilen, die der andere zusammenhält.

14

Einstellungen im Überblick

Das Erkennungsverhalten wird durch plattformweite Einstellungen gesteuert, die zentral abgestimmt werden und nicht pro Asset gelten. Sie sind hier aufgeführt, damit Sie einordnen können, was Sie sehen — nicht, weil Sie sie ändern müssten.

EinstellungStandardWas sie steuert
Ankerradius100 mWie weit eine Meldung vom Ankerpunkt eines Stopps entfernt sein darf und trotzdem zu diesem Stopp zählt
Mindestdistanz Etappe300 mWie weit sich eine Bewegung vom Ausgangspunkt entfernen muss, um als Etappe erfasst zu werden
Mindestauslenkung Etappe500 mErmöglicht, dass Hin- und Rückfahrten nach der zurückgelegten Strecke zählen und nicht nach dem Endpunkt
Stabilisierungszeit3 Min.Wie lange ein Asset an einem Ort bleiben muss, bevor eine Ankunft festgeschrieben wird
Standzeit für Fahrtunterbrechung30 Min.Längere Stopps beenden die Fahrt; kürzere sind Zwischenpunkte innerhalb der Fahrt
Timeout bei Meldelücke30 Min.Längeres Schweigen schließt die laufende Etappe ab
→ Änderungen wirken ab sofort in die Zukunft

Eine Anpassung dieser Einstellungen betrifft nur künftige Verarbeitungen. Bereits aufgebaute Fahrten werden nicht neu berechnet, sodass Ihre Historie mit der ursprünglichen Auswertung konsistent bleibt.

15

Fehlerbehebung

Mein Asset steht nicht in der Movement-Analytics-Liste

Die Liste zeigt nur Assets mit aktiviertem Advanced Trip Analysis. Bearbeiten Sie das Asset über Assets und setzen Sie im Dialog Edit Tag das Häkchen bei Enable Advanced Trip Analysis. Ist es ausgegraut, muss ein Systemadministrator die Funktion aktivieren.

Ich habe das Häkchen gesetzt, aber es gibt keine Historie

Advanced Trip Analysis wirkt nur vorwärts. Fahrten entstehen ab dem nächsten Positionsabruf — für den Zeitraum davor gibt es nichts anzuzeigen. Warten Sie ein, zwei Fahrten ab und prüfen Sie dann erneut.

Benötigen Sie gerade den früheren Zeitraum, richten Sie eine Anfrage an Ihren Administrator, um das weitere Vorgehen abzustimmen.

Eine Fahrt wird als gerade Linie statt entlang der Straße dargestellt

Das Asset hat während dieser Etappe nur wenige Male gemeldet. Die Linie wird durch die vorhandenen Positionen gezogen, eine Etappe mit drei Meldungen erscheint daher als zwei gerade Abschnitte. Prüfen Sie die Registerkarte Positions, um die tatsächliche Meldehäufigkeit in diesem Zeitfenster zu sehen.

Eine Fahrt, die ich gemacht habe, wird nicht angezeigt

Meist hat sich die Bewegung nicht weit genug entfernt, um als Etappe zu gelten — sehr kurze Wege werden bewusst herausgefiltert. Trifft das nicht zu, prüfen Sie den Zeitraum und sehen Sie in der Registerkarte Positions nach, ob das Asset in dieser Zeit überhaupt gemeldet hat.

Ein Stopp wird als zwei angezeigt

Positionsstreuung kann Meldungen gelegentlich so weit auseinanderziehen, dass ein einzelner Stopp in Teilen erfasst wird. Am wahrscheinlichsten ist das bei verrauschten Positionsdaten oder auf einer großen Parkfläche. Die Registerkarte Positions zeigt, ob die Meldungen tatsächlich weit gestreut waren.

Zwei Tags im selben Fahrzeug zeigen unterschiedliche Fahrten

Vergleichen Sie Gesamtdistanz und Etappenzahl statt der Anzahl der Fahrten. Fahrtgrenzen hängen von der Stoppdauer ab, deshalb kann ein Stopp nahe der 30-Minuten-Schwelle den Tag des einen Tags berechtigterweise teilen und den des anderen nicht. Große Abweichungen bei der Distanz sollten Sie hingegen melden.

Die Karte ist nach Plot all unübersichtlich

Engen Sie den Zeitraum ein oder verwenden Sie Clear markers und wählen Sie eine einzelne Fahrt aus. Die Kopfzeile des Fahrtenbereichs zeigt, wie viele Fahrten aktuell einbezogen sind.

16

FAQ

Brauche ich spezielle Hardware?

Nein. Movement Analytics nutzt die Positionsmeldungen, die Ihre Assets ohnehin senden.

Kann ich Movement Analytics selbst aktivieren?

Nur als Systemadministrator. Andere Benutzer können sehen, ob Advanced Trip Analysis für ein Asset aktiv ist, es aber nicht ändern.

Baut das Aktivieren von Advanced Trip Analysis vergangene Fahrten auf?

Nein. Die Verarbeitung beginnt mit dem nächsten Positionsabruf. Alles davor wird nicht rekonstruiert.

Können historische Daten erneut verarbeitet werden?

Nicht vom Asset aus. Benötigen Sie Fahrten für einen Zeitraum vor der Aktivierung von Advanced Trip Analysis, richten Sie eine Anfrage an Ihren Administrator, um das weitere Vorgehen abzustimmen.

Was passiert, wenn ich es wieder ausschalte?

Vorhandene Fahrten bleiben sichtbar. Neue entstehen erst wieder, wenn Sie die Funktion erneut aktivieren.

Warum ist die Distanz einer Fahrt geringer als mein Tachostand?

Die Distanz wird zwischen gemeldeten Positionen gemessen, jede Kurve zwischen zwei Meldungen zählt also als gerade Linie. Assets, die selten melden, liegen unter der tatsächlichen Straßendistanz.

Warum erscheinen Stopps manchmal, bevor das Asset weitergefahren ist?

Stopps werden angezeigt, während sie noch laufen, mit einer Standzeit, die mit jeder Meldung wächst. Sie müssen die Abfahrt nicht abwarten, um den aktuellen Stopp zu sehen.

Kann ich Fahrten exportieren?

Positionsdaten lassen sich aus der Tracking-Plattform exportieren. Ein Export auf Fahrtenebene steht auf der Roadmap.

Werden Flüge erkannt?

Die automatische Erkennung von Flugreisen steht auf der Roadmap. Bis dahin wird ein Flug als gewöhnliche Fahrt mit einer einzigen sehr langen Etappe erfasst.

Wie weit reicht die Historie zurück?

So weit zurück, wie Advanced Trip Analysis für das Asset aktiviert war und Positionen aufbewahrt wurden. Verwenden Sie Custom im Zeitraum, um ein bestimmtes Zeitfenster zu betrachten.

Funktioniert Movement Analytics mit jedem Tag-Typ?

Jedes Asset in Beacon Telematics, das Positionen meldet, kann Advanced Trip Analysis aktiviert bekommen. Wie detailliert die Route ausfällt, hängt davon ab, wie häufig der Tag meldet.
